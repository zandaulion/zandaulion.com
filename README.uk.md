# Zandaulion

Грайлива майстерня для допитливих ідей: застосунки, ігри та невеликі інструменти для відкриттів.

**[Відвідайте zandaulion.com](https://zandaulion.com/)** · [Румунська колекція](https://zandaulion.com/ro/index.html)

Це сховище містить веб-сайт Zandaulion: доступну для пошуку колекцію з 20 проектів, окремі сторінки проектів та інтерактивний редактор діаграм Sankey. Домашня сторінка та кожна сторінка проекту доступні 12 мовами. Сайт є статичним HTML, CSS і ванільним JavaScript, розміщеним на GitHub Pages.

## Переклади README

Цей файл README доступний тими ж 12 мовами, що й веб-сайт. Використовуйте мовні посилання вгорі, щоб перемикати версії. Англійська мова живе в `README.md`; перекладені версії використовують такі імена файлів, як `README.ro.md` і `README.ar.md`.

Відредагуйте README англійською мовою та відповідні каталоги в `locales/readme/`, а потім запустіть `python scripts/build_readmes.py`, щоб повторно створити перекладені файли. Використовуйте `python scripts/build_readmes.py --check` для виявлення застарілих файлів або відсутніх перекладів. Додатковий прапор `--fetch` готує відсутні чернетки перекладу через ту саму службу перекладу Google, яка використовується для тексту проекту. Команди, шляхи, приклади коду та призначення посилань зберігаються.

## Що тут є

- Колекція з фільтрами категорій, пошуком без наголосу та випадковим пошуком.
- Описи проектів, посилання на запуск і джерело, галереї знімків екрана та пов’язані проекти.
- Доступні за допомогою клавіатури галереї зображень із підписами, попередніми/наступними елементами керування та жестами дотику.
- Редактор Sankey із редагуванням вузлів/посилань, експортом зображень та імпортом/експортом JSON.
- Вибір мови, збережені налаштування, визначення мови браузера та арабська розкладка справа наліво.
- Існуючі повідомлення про конфіденційність англійською мовою на URL-адресах, уже зареєстрованих у Google Play.

## Локальний попередній перегляд

Виконайте ці команди з кореня сховища. Python потрібен для генератора і чеків; сценарії Python використовують лише стандартну бібліотеку. Для мовних тестів потрібен Node.js із вбудованим запуском тестів. Немає етапу встановлення npm або інтерфейсу комплектування.

```sh
python scripts/build_locales.py
python -m http.server 8765 --bind 127.0.0.1
```

Відкрийте [локальну домашню сторінку](http://127.0.0.1:8765/index.html) або скористайтеся [явною англійською](http://127.0.0.1:8765/index.html?lang=en-US) або [Rumunian](http://127.0.0.1:8765/ro/index.html), щоб обійти автоматичний вибір мови.

Згенерований HTML також призначений для прямого перегляду файлів. Відкрийте `index.html`, а не мовну папку; навігація використовує чіткі імена файлів, щоб уникнути списків каталогів. Мовні сценарії — це звичайні скрипти, а не модулі ES. Локальний попередній перегляд HTTP є рекомендованим способом перегляду змін.

Перекладені сторінки проекту зберігають ту саму назву файлу під префіксом мови, наприклад `/fr/kerfloom.html` або `/ja/plate.html`. Перемикання мови зберігає прив’язку поточного проекту та розділу. Посилання на колекцію та пов’язані проекти залишаються вибраною мовою. Кожна домашня сторінка та сторінка проекту мають декларацію мови, канонічну URL-адресу та взаємні посилання `hreflang`.

Явний мовний шлях, наприклад `/ro/`, завжди має пріоритет. Лише на головній сторінці входу (`/` або `/index.html`) вибір відбувається в такому порядку:

1. Підтримуваний явний вибір `?lang=`.
2. Збережене налаштування мови.
3. Перше підтримуване налаштування браузера від `navigator.languages`.
4. Англійська, якщо не знайдено жодної підтримуваної мови.

Регіональні варіанти відповідають базовій мові: наприклад, `fr-CA` вибирає французьку. Посилання англійською мовою включають `?lang=en-US`, тому явний вибір працює, навіть якщо сховище браузера недоступне. Переспрямування початкової сторінки зберігають прив’язки розділів та інші параметри запиту. URL-адреси проекту та конфіденційності ніколи не переспрямовують на основі мови веб-переглядача.

Мовні посилання на домашню сторінку присутні в HTML і працюють без JavaScript. Заголовки проектів, їхні засоби вибору мови, елементи керування галереєю та редактор Sankey використовують JavaScript. Посилання на локальний файл проекту містять вибрану мову в URL-адресі, оскільки браузери можуть ізолювати сховище для кожного файлу.

## Редагування та створення сторінок

| Що змінити | Джерело для редагування |
| --- | --- |
| Макет домашньої сторінки | `templates/home.html` |

| Перекладений зміст проекту | `locales/projects/<locale>/<project>.json` |
| Елементи керування галереєю та повідомлення редактора | `locales/projects/<locale>/common.json` |
| Багаторазові виправлення перекладу | `locales/projects/overrides.json` |
| Підтримувані локалі та префікси URL-адрес | `scripts/site_locales.py` |
| Охоплення проекту та рендеринг перекладу | `scripts/project_locales.py` |
| Спільна презентація | `workshop.css` і `project.css` |
| Колекція, проект і поведінка мови | `workshop.js`, `project.js` і `language.js` |
| Поведінка редактора Sankey | `sankey.js` |

Після редагування вихідного вмісту або каталогів повторно згенеруйте сайт:

```sh
python scripts/build_locales.py
```

Генератор створює 12 домашніх сторінок, 220 перекладених сторінок проекту та `language-data.js`. Він також підтримує канонічні та іншомовні посилання на 20 сторінках англійського проекту. Зафіксуйте ці згенеровані виходи з їх джерелами; GitHub Pages обслуговує їх безпосередньо без запуску генератора Python.

Не редагуйте створені домашні сторінки, перекладені HTML або `language-data.js` напряму: відновлення замінює ці редагування. Каталоги домашніх сторінок повинні мати відповідні непорожні ключі. Каталоги проекту використовують вихідний текст як ключі, тому зміни англійської копії вимагають відповідних оновлень перекладу. Відсутні переклади заважають збірці.

### Підтримка перекладів

Чернетки перекладу проекту були підготовлені за допомогою служби перекладу Google, потім уточнено спільні формулювання, елементи керування галереєю, назви продуктів і вибрані технічні фрази. Раніше румунські переклади були збережені. Огляд носія мови все ще корисний, особливо для технічної термінології. Назви програм, знімки екрана та технічні ідентифікатори зберігають свою оригінальну форму.

Додатковий авторський сценарій може підготувати відсутні переклади для однієї мови:

```sh
python scripts/translate_projects.py --fetch --language ro
```

Пропустіть `--language ro`, щоб обробити всі перекладені локалі. Прапор `--fetch` дозволяє надсилати відсутній публічний текст проекту до служби перекладу Google. Існуючі каталоги використовуються повторно, назви продуктів захищено, а `overrides.json` застосовано виправлення. Без `--fetch` сценарій повідомляє про відсутні рядки та оновлює каталоги лише там, де всі необхідні переклади вже доступні. Це не перевірка лише для читання.

Деякі спільні фрази також зустрічаються в каталогах для кожного проекту. Внесіть узгоджені виправлення формулювання в `overrides.json` і запустіть підготовчий сценарій, щоб застосувати їх у всіх проектах, а потім перебудуйте HTML. Перегляньте згенеровані переклади перед публікацією. Git ігнорує папку `.translation-cache/`. Звичайні збірки та розгорнутий веб-сайт ніколи не викликають службу перекладу.

## Перевірки перед публікацією

Запустивши локальний сервер попереднього перегляду, виконайте ці команди в іншому терміналі:

```sh
python scripts/build_locales.py --check
python scripts/check_site.py --url http://127.0.0.1:8765
node --test scripts/test_language.cjs
```

- Перевірка збірки виявляє застарілі згенеровані виходи та відсутні переклади.
- Перевірка сайту охоплює всі 261 сторінку HTML: 12 домашніх сторінок, 240 сторінок проекту, вісім повідомлень про конфіденційність і одне перенаправлення сумісності. Він перевіряє локальні посилання, активи, повторювані ідентифікатори за межами збереженої розмітки конфіденційності, метадані мови проекту, взаємні посилання SEO та арабський напрямок. За допомогою `--url` він також перевіряє відповіді HTTP і порівнює надані повідомлення про конфіденційність із їхніми вихідними файлами.
- Мовні тести охоплюють пріоритет налаштувань, регіональну відповідність, заблоковане сховище, корені файлів і підкаталогів, поведінку перенаправлення та збереження розділів.

Для перевірки офлайн-посилань запустіть `python scripts/check_site.py` без `--url`. Перегляньте також уражені сторінки у веб-переглядачі: мобільний макет, арабський напрямок, перемикання мов, елементи керування клавіатурою галереї та взаємодію редактора.

## Розгортання

Активний сайт – [zandaulion.com](https://zandaulion.com/), опублікований від `main` до GitHub Pages. `CNAME` зберігає спеціальну конфігурацію домену.

Після створення та перевірки сайту зафіксуйте джерело та згенеровані зміни та натисніть `main`. Зачекайте, доки завершиться робочий процес збірки та розгортання **pages build and deployment**, а потім перевірте змінені URL-адреси в активному домені. Зберігайте існуючий проект і маршрути конфіденційності під час перейменування програм або їхніх сховищ.

Сайт використовує статичні ресурси та звичайні скрипти. Шрифти завантажуються з Google Fonts, а редактор Sankey завантажує Apache ECharts з jsDelivr. Під час виконання не потрібна служба перекладу.
