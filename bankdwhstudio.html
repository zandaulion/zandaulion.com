Bank DWH Studio

Ask a banking question. Explore the relevant schema. Leave with an editable SQL draft.

Open the PWA View on GitHub

The live PWA is invitation-only.

A question becomes something you can inspect

Bank DWH Studio is a personal proof of concept for exploring a large banking data warehouse through natural language. Ask a question, optionally choose a banking subject area, and the app retrieves the most relevant schema context before drafting PostgreSQL SQL.

The result is deliberately more than a code block. It shows the retrieved tables, interpretation, assumptions, review notes, and basic checks beside an editable draft. When a necessary detail is missing—such as the year in an end-of-August request—the assistant can ask for clarification.

How it works

  1. Ask in everyday language. Describe the banking answer you need and narrow the search to a subject area when useful.
  2. Retrieve a bounded slice of the schema. A Node backend searches Elasticsearch metadata for relevant tables and columns.
  3. Draft with context. A hosted GPT-OSS model creates SQL from that bounded schema, while catalog-grounded rules handle supported common questions.
  4. Review before using. Edit or copy the draft, inspect its context and assumptions, then run it separately in your own SQL client.

What is on the workbench

100 synthetic tables

A generated banking warehouse fixture provides 5,000 columns, relationships, PostgreSQL DDL, a catalog, and a small seed.

Schema-grounded retrieval

Elasticsearch narrows a large catalog to the metadata needed for the question before anything is sent to the model.

Visible reasoning context

Retrieved tables, interpretation, assumptions, notes, and checks stay visible so the draft can be challenged rather than accepted blindly.

One PWA, many screens

The invite-only interface is installable and adapts from wide desktop screens to compact phones.

Gallery

Six questions across desktop, laptop, tablet, and phone. These captures replay reviewed responses generated against the synthetic catalog, making the portfolio examples repeatable.

The human stays in the loop

The app drafts SQL; it never connects to a banking warehouse and never executes a query. Users edit or copy the result and run it separately in their own database client. The browser never receives the model API key.

Automated checks cover read-only statement shape and known table references. SQL syntax, column references, and business meaning still require human review. All warehouse names, relationships, and measures in the repository are synthetic test material rather than approved banking definitions.

Under the hood

The deployed proof of concept runs a Node backend on an Oracle Ampere A1 instance, with Elasticsearch for schema retrieval and a hosted GPT-OSS model for SQL drafting. The repository also documents a broader future architecture, clearly separated from the smaller deployed POC.
