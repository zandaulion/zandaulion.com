# Zandaulion

जिज्ञासु विचारों की एक मज़ेदार कार्यशाला: खोजने के लिए ऐप, गेम और छोटे उपकरण।

**[zandaulion.com पर जाएँ](https://zandaulion.com/)** · [रोमानियाई संग्रह](https://zandaulion.com/ro/index.html)

इस रिपॉजिटरी में Zandaulion वेबसाइट शामिल है: 21 परियोजनाओं, व्यक्तिगत प्रोजेक्ट पेजों और एक इंटरैक्टिव Sankey आरेख संपादक का खोजने योग्य संग्रह। मुखपृष्ठ और प्रत्येक परियोजना पृष्ठ 12 भाषाओं में उपलब्ध हैं। साइट स्थिर HTML, CSS, और वेनिला JavaScript है, जो GitHub Pages पर होस्ट की गई है।

## README के अनुवाद

यह README वेबसाइट की तरह ही 12 भाषाओं में उपलब्ध है। संस्करण बदलने के लिए शीर्ष पर स्थित भाषा लिंक का उपयोग करें। अंग्रेजी `README.md` में रहती है; अनुवादित संस्करण `README.ro.md` और `README.ar.md` जैसे फ़ाइल नामों का उपयोग करते हैं।

अंग्रेजी README और संबंधित कैटलॉग को `locales/readme/` में संपादित करें, फिर अनुवादित फ़ाइलों को पुन: उत्पन्न करने के लिए `python scripts/build_readmes.py` चलाएँ। पुरानी फ़ाइलों या गुम अनुवादों का पता लगाने के लिए `python scripts/build_readmes.py --check` का उपयोग करें। वैकल्पिक `--fetch` ध्वज प्रोजेक्ट टेक्स्ट के लिए उपयोग की जाने वाली उसी Google अनुवाद सेवा के माध्यम से लापता अनुवाद ड्राफ्ट तैयार करता है। आदेश, पथ, कोड उदाहरण और लिंक गंतव्य संरक्षित हैं।

## स्थानीय पूर्वावलोकन

इन कमांड को रिपॉजिटरी रूट से चलाएँ। जनरेटर और जांच के लिए Python की आवश्यकता है; Python स्क्रिप्ट केवल मानक लाइब्रेरी का उपयोग करती हैं। भाषा परीक्षणों के लिए बिल्ट-इन टेस्ट रनर के साथ Node.js की आवश्यकता होती है। कोई npm इंस्टॉल या फ्रंटएंड बंडलर चरण नहीं है।

```sh
python scripts/build_locales.py
python -m http.server 8765 --bind 127.0.0.1
```

[स्थानीय मुखपृष्ठ](http://127.0.0.1:8765/index.html) खोलें, या स्वचालित भाषा चयन को बायपास करने के लिए [स्पष्ट अंग्रेजी](http://127.0.0.1:8765/index.html?lang=en-US) या [रोमानियाई](http://127.0.0.1:8765/ro/index.html) का उपयोग करें।

उत्पन्न HTML को सीधे फ़ाइल ब्राउज़िंग के लिए भी डिज़ाइन किया गया है। `index.html` खोलें, भाषा फ़ोल्डर नहीं; निर्देशिका सूची से बचने के लिए नेविगेशन स्पष्ट फ़ाइल नामों का उपयोग करता है। भाषा स्क्रिप्ट ईएस मॉड्यूल के बजाय सामान्य स्क्रिप्ट हैं। स्थानीय HTTP पूर्वावलोकन परिवर्तनों की समीक्षा करने का अनुशंसित तरीका है।

अनुवादित प्रोजेक्ट पृष्ठ भाषा उपसर्ग के अंतर्गत समान फ़ाइल नाम रखते हैं, जैसे `/fr/kerfloom.html` या `/ja/plate.html`। भाषा स्विचिंग वर्तमान प्रोजेक्ट और सेक्शन को एंकर बनाए रखती है। संग्रह और संबंधित-परियोजना लिंक चयनित भाषा में रहते हैं। प्रत्येक होमपेज और प्रोजेक्ट पेज में एक भाषा घोषणा, कैनोनिकल यूआरएल और पारस्परिक `hreflang` लिंक हैं।

एक स्पष्ट भाषा पथ, जैसे `/ro/`, को हमेशा प्राथमिकता दी जाती है। केवल मुख्य प्रविष्टि पृष्ठ (`/` या `/index.html`) पर, चयन इस क्रम का अनुसरण करता है:

1. एक समर्थित स्पष्ट `?lang=` विकल्प।
2. एक सहेजी गई भाषा प्राथमिकता.
3. `navigator.languages` से पहली समर्थित ब्राउज़र प्राथमिकता।
4. यदि कोई समर्थित भाषा मेल नहीं खाती तो अंग्रेजी।

क्षेत्रीय संस्करण उनकी मूल भाषा से मेल खाते हैं: उदाहरण के लिए, `fr-CA` फ़्रेंच का चयन करता है। अंग्रेजी लिंक में `?lang=en-US` शामिल है इसलिए ब्राउज़र स्टोरेज अनुपलब्ध होने पर भी एक स्पष्ट विकल्प काम करता है। एंट्री-पेज रीडायरेक्ट सेक्शन एंकर और अन्य क्वेरी पैरामीटर को संरक्षित करता है। प्रोजेक्ट और गोपनीयता यूआरएल कभी भी ब्राउज़र भाषा के आधार पर रीडायरेक्ट नहीं होते हैं।

होमपेज भाषा लिंक HTML में मौजूद हैं और JavaScript के बिना काम करते हैं। प्रोजेक्ट हेडर, उनका भाषा पिकर, गैलरी नियंत्रण और Sankey संपादक JavaScript का उपयोग करते हैं। स्थानीय-फ़ाइल प्रोजेक्ट लिंक URL में चयनित भाषा रखते हैं क्योंकि ब्राउज़र प्रत्येक फ़ाइल के लिए भंडारण को अलग कर सकते हैं।

## पृष्ठ संपादित करना और बनाना

| क्या बदलना है | संपादित करने के लिए स्रोत |
| --- | --- |
| मुखपृष्ठ लेआउट | `templates/home.html` |
| प्रत्येक भाषा में मुखपृष्ठ पाठ | `locales/<locale>.json` |
| अंग्रेजी परियोजना सामग्री और लेआउट | रूट प्रोजेक्ट HTML फ़ाइलें, जैसे `kerfloom.html` |
| अनुवादित परियोजना सामग्री | `locales/projects/<locale>/<project>.json` |
| गैलरी नियंत्रण और संपादक संदेश | `locales/projects/<locale>/common.json` |
| पुन: प्रयोज्य अनुवाद सुधार | `locales/projects/overrides.json` |
| समर्थित स्थान और यूआरएल उपसर्ग | `scripts/site_locales.py` |
| परियोजना कवरेज और अनुवाद प्रतिपादन | `scripts/project_locales.py` |
| साझा प्रस्तुति | `workshop.css` और `project.css` |
| संग्रह, परियोजना और भाषा व्यवहार | `workshop.js`, `project.js`, और `language.js` |
| Sankey संपादक व्यवहार | `sankey.js` |

स्रोत सामग्री या कैटलॉग को संपादित करने के बाद, साइट को पुनर्जीवित करें:

```sh
python scripts/build_locales.py
```

जनरेटर 12 होमपेज, 220 अनुवादित प्रोजेक्ट पेज और तैयार करता है `language-data.js`. यह 20 अंग्रेजी परियोजना पृष्ठों पर विहित और वैकल्पिक भाषा लिंक भी बनाए रखता है। इन उत्पन्न आउटपुट को उनके स्रोतों के साथ प्रतिबद्ध करें; GitHub Pages बिना चलाए उन्हें सीधे सेवा प्रदान करता है Python जेनरेटर.

जनरेट किए गए मुखपृष्ठों, अनुवादित HTML, या `language-data.js` को सीधे संपादित न करें: पुनर्जनन उन संपादनों को प्रतिस्थापित कर देता है। मुखपृष्ठ कैटलॉग में मिलान वाली गैर-रिक्त कुंजियाँ होनी चाहिए। प्रोजेक्ट कैटलॉग स्रोत पाठ को कुंजी के रूप में उपयोग करते हैं, इसलिए अंग्रेजी प्रतिलिपि में परिवर्तन के लिए संबंधित अनुवाद अद्यतन की आवश्यकता होती है। अनुपलब्ध अनुवाद निर्माण को विफल कर देते हैं।

### अनुवादों का रखरखाव

प्रोजेक्ट अनुवाद ड्राफ्ट Google की अनुवाद सेवा के साथ तैयार किए गए, फिर साझा शब्दांकन, गैलरी नियंत्रण, उत्पाद नाम और चयनित तकनीकी वाक्यांशों को परिष्कृत किया गया। पहले के रोमानियाई अनुवादों को बरकरार रखा गया था। मूल-वक्ता समीक्षा अभी भी उपयोगी है, विशेषकर तकनीकी शब्दावली के लिए। ऐप के नाम, स्क्रीनशॉट और तकनीकी पहचानकर्ता अपना मूल स्वरूप बरकरार रखते हैं।

वैकल्पिक संलेखन स्क्रिप्ट एक स्थान के लिए लापता अनुवाद तैयार कर सकती है:

```sh
python scripts/translate_projects.py --fetch --language ro
```

सभी अनुवादित स्थानों को संसाधित करने के लिए `--language ro` को छोड़ दें। `--fetch` ध्वज लापता सार्वजनिक प्रोजेक्ट टेक्स्ट को Google की अनुवाद सेवा में भेजने की अनुमति देता है। मौजूदा कैटलॉग का पुन: उपयोग किया जाता है, उत्पाद नाम सुरक्षित किए जाते हैं, और `overrides.json` सुधार लागू किए जाते हैं। `--fetch` के बिना, स्क्रिप्ट गुम स्ट्रिंग्स की रिपोर्ट करती है और केवल कैटलॉग को रीफ्रेश करती है जहां सभी आवश्यक अनुवाद पहले से ही उपलब्ध हैं। यह केवल पढ़ने योग्य जाँच नहीं है.

कुछ साझा वाक्यांश प्रति-प्रोजेक्ट कैटलॉग में भी होते हैं। `overrides.json` में लगातार शब्दों में सुधार करें और उन्हें परियोजनाओं में लागू करने के लिए तैयारी स्क्रिप्ट चलाएं, फिर HTML का पुनर्निर्माण करें। प्रकाशन से पहले उत्पन्न अनुवादों की समीक्षा करें। `.translation-cache/` फ़ोल्डर को Git द्वारा अनदेखा कर दिया गया है। सामान्य बिल्ड और तैनात वेबसाइट कभी भी अनुवाद सेवा को कॉल नहीं करती है।

## प्रकाशन से पहले जाँच

स्थानीय पूर्वावलोकन सर्वर चलने के साथ, इन आदेशों को दूसरे टर्मिनल में चलाएँ:

```sh
python scripts/build_locales.py --check
python scripts/check_site.py --url http://127.0.0.1:8765
node --test scripts/test_language.cjs
```

- बिल्ड चेक पुराने जनरेट किए गए आउटपुट और गुम अनुवाद का पता लगाता है।
- साइट जांच में सभी 261 HTML पेज शामिल हैं: 12 होमपेज, 240 प्रोजेक्ट पेज, आठ गोपनीयता नोटिस और एक संगतता रीडायरेक्ट। यह स्थानीय लिंक, संपत्ति, संरक्षित गोपनीयता मार्कअप के बाहर डुप्लिकेट आईडी, प्रोजेक्ट भाषा मेटाडेटा, पारस्परिक SEO लिंक और अरबी दिशा की जांच करता है। `--url` के साथ, यह HTTP प्रतिक्रियाओं की भी जांच करता है और उनकी स्रोत फ़ाइलों के साथ दी गई गोपनीयता सूचनाओं की तुलना करता है।
- भाषा परीक्षणों में प्राथमिकता प्राथमिकता, क्षेत्रीय मिलान, अवरुद्ध भंडारण, फ़ाइल और उपनिर्देशिका जड़ें, पुनर्निर्देशन व्यवहार और अनुभाग संरक्षण शामिल हैं।

ऑफ़लाइन लिंक जाँच के लिए, `--url` के बिना `python scripts/check_site.py` चलाएँ। ब्राउज़र में प्रभावित पृष्ठों की भी समीक्षा करें: मोबाइल लेआउट, अरबी दिशा, भाषा स्विचिंग, गैलरी कीबोर्ड नियंत्रण और संपादक इंटरैक्शन।

## परिनियोजन

लाइव साइट [zandaulion.com](https://zandaulion.com/) है, जो `main` से GitHub Pages तक प्रकाशित हुई है। `CNAME` कस्टम डोमेन कॉन्फ़िगरेशन रखता है।

साइट बनाने और जाँचने के बाद, स्रोत और उत्पन्न परिवर्तन करें और `main` पुश करें। **pages build and deployment** वर्कफ़्लो के पूरा होने तक प्रतीक्षा करें, फिर लाइव डोमेन पर बदले गए URL को सत्यापित करें। ऐप्स या उनके रिपॉजिटरी का नाम बदलते समय मौजूदा प्रोजेक्ट और गोपनीयता मार्गों को रखें।

साइट स्थिर परिसंपत्तियों और साधारण स्क्रिप्ट का उपयोग करती है। फ़ॉन्ट्स Google Fonts से लोड किए जाते हैं, और Sankey संपादक jsDelivr से Apache ECharts लोड करता है। रनटाइम पर किसी अनुवाद सेवा की आवश्यकता नहीं है.
