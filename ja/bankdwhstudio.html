Bank DWH Studio

質問は調べられるものになる

Bank DWH Studio は、自然言語を通じて大規模な銀行データ ウェアハウスを探索するための個人的な概念実証です。質問をし、必要に応じて銀行のサブジェクト領域を選択すると、アプリは PostgreSQL SQL を作成する前に最も関連性の高いスキーマ コンテキストを取得します。

結果は意図的にコードブロック以上のものになります。編集可能なドラフトの横に、取得した表、解釈、仮定、レビューメモ、および基本的なチェックが表示されます。 8 月末のリクエストの年など、必要な詳細が不足している場合、アシスタントは説明を求めることができます。

仕組み

  1. 日常の言葉で尋ねてください。 必要な銀行業務に関する回答を説明し、必要に応じて対象分野に検索を絞り込みます。
  2. スキーマの境界付きスライスを取得します。 Node バックエンドは、関連するテーブルと列の Elasticsearch メタデータを検索します。
  3. コンテキストを含めて下書きします。 ホストされた GPT-OSS モデルは、その制限されたスキーマから SQL を作成しますが、カタログに基づいたルールは、サポートされている一般的な質問を処理します。
  4. 使用する前に確認してください。 ドラフトを編集またはコピーし、そのコンテキストと仮定を検査して、独自の SQL クライアントで個別に実行します。

取得した表、解釈、仮定、メモ、チェックは表示されたままになるため、ドラフトを盲目的に受け入れるのではなく異議を唱えることができます。

ギャラリー

デスクトップ、ラップトップ、タブレット、携帯電話にわたる 6 つの質問。これらのキャプチャは、合成カタログに対して生成されたレビュー済みの応答を再生し、ポートフォリオの例を再現可能にします。

人間は常にループの中にいます

このアプリは SQL の草案を作成するだけで、銀行のデータウェアハウスに接続したり、クエリを実行したりすることはありません。利用者は結果を編集またはコピーし、自分のデータベースクライアントで別途実行します。ブラウザーにモデルの API キーが渡ることはありません。

自動チェックの対象は、読み取り専用ステートメントの基本形と既知のテーブル参照です。SQL の構文、列参照、業務上の意味は引き続き人による確認が必要です。ウェアハウス内の名称、関係、指標はすべて合成したテスト資料であり、承認済みの銀行業務定義ではありません。

ボンネットの下で

デプロイされた概念実証では、Oracle Ampere A1 インスタンス上で Node バックエンドを実行し、スキーマ取得用の Elasticsearch と、SQL ドラフト用のホストされた GPT-OSS モデルを使用します。このリポジトリには、小規模に展開された POC から明確に分離された、より広範な将来のアーキテクチャも文書化されています。
